# Realistic scientific instrument drawing

Use this reference when the user asks for an instrument that is realistic, photo-like, high-detail or close to an actual laboratory device. The result remains an editable vector illustration, not a photograph.

## Visual target

- Begin with the exterior form seen in a real laboratory: credible width-to-height ratio, chassis depth, doors, panel seams, source or sample interface, ventilation, feet and service access. A simplified internal schematic must not replace the exterior unless the user asks for a cutaway.
- Use a three-quarter view when it materially improves depth. Establish a consistent front, side and top plane before adding details.
- Separate painted metal, polymer, glass, rubber, brushed metal and illuminated displays through restrained gradients, transparency, highlights and edge shadows. Avoid flat blocks, heavy cartoon outlines and arbitrary glossy decoration.
- Include the minimum functional hardware that makes the class identifiable. For example, a Q-TOF MS should show an ion-source interface, a substantial analyzer housing, high-vacuum/service areas, status or acquisition controls, ventilation and realistic LC/gas connections.
- Keep manufacturer-neutral proportions and controls unless the user supplies a reference and has permission to reproduce it. Do not add logos, product names, certification labels or a copied vendor silhouette.

## Editable construction

Use semantic groups for chassis, source/sample interface, analyzer housing, doors, display, controls, vents, tubing, highlights and cast shadow. In PowerPoint, use native shapes and editable text. In Illustrator, use paths, live text and native gradients. Do not flatten the final instrument into a bitmap.

## Fast high-detail path

Speed means fewer redundant passes, not fewer defining details.

1. Select the instrument class and list five to eight defining exterior parts before drawing.
2. Reuse validated generic construction patterns for chassis panels, glass windows, vents, displays, feet, tubing and material highlights. Adjust proportions and arrangement to the requested instrument.
3. Build in one planned sequence: silhouette and perspective, functional hardware, material/light layer, then small controls and seams.
4. Write to the target application once after local structural inspection. Prefer correcting the inserted group in place over creating repeated full copies.
5. Inspect one full-slide render and one enlarged critical region. Repeat only when a specific defect is visible.

Do not perform extra category renders, broad asset-library tests or unrelated compatibility checks for a single instrument request. Still validate the actual deliverable, confirm native editability in the requested app, and preserve existing user artwork.

## Acceptance checks

- The instrument remains recognizable without its label.
- Exterior proportions, perspective and contact shadow agree.
- Ports, doors, tubing, vents and controls attach to plausible surfaces.
- Highlights follow one light direction and do not cross panel seams.
- No label overlap, clipped shape, accidental transparency or detached functional component is visible at normal size or 200%.
